Transformers Process Supervision Mechanistic Interpretability

Hand-Coded Process and Outcome Programs in One Transformer

By Aayushman

October 1, 2026 · IIT Madras · Interactive note · 14 min read

When we train a small two-block Transformer on modular letter counting, process supervision (training the model to write every intermediate state $s_1, \dots, s_n$ before the final answer) reliably learns the task, whereas outcome supervision (training it to write only the final answer $s_n$) stays stuck at chance. Could that failure simply be expressive—that a two-block network without intermediate tokens cannot represent the outcome solution?

To rule out expressivity, we write the exact weights of both solutions by hand into the exact same two-block causal Transformer. Both programs use the same parameter tensors with the exact same shapes; only the numerical values in Block 1 and four readout entries differ. Every diagram, activation table, and matrix product on this page is computed live in your browser by running those exact weights on the running example ($s_0 = 1,\ q = \mathtt{a},\ \text{word} = \mathtt{b\,a\,d\,a}$, modulus $m = 2$).

1. The Task and the Sequence Encoding

Each prompt consists of an initial state $s_0 \in \{0, \dots, m-1\}$, a query letter $q$ from an alphabet of size $A$, and a word $w_1 \dots w_n$ of length $n$. After reading letter $w_t$, the state increments by $1$ modulo $m$ if $w_t$ matches $q$:

\[ s_t = (s_{t-1} + b_t) \bmod m, \qquad b_t = \mathbf{1}[w_t = q]. \]

We call $b_t \in \{0, 1\}$ the mark of letter $t$, and $c = \sum_{t=1}^n b_t$ the total number of marks in the word.

Vocabulary and Position Indexing

To represent prompts, intermediate states, and answers as a single token sequence, we use a vocabulary of $|\mathcal{V}| = A + m + 3$ distinct tokens:

  • Letter tokens ($0, \dots, A-1$): represent the alphabet letters ($\mathtt{a, b, c, d}$).
  • State-value tokens ($A, \dots, A + m - 1$): represent state integers $v \in \{0, \dots, m-1\}$ as separate token IDs $A + v$, so a state digit $0$ or $1$ is never confused with a letter token.
  • Delimiters ($A+m,\ A+m+1,\ A+m+2$): $\textsc{sep}$ (end of prompt), $\mathtt{:}$ (before the final answer), and $\textsc{eos}$ (end of sequence).

Positions are 0-indexed ($0, 1, \dots, P-1$), where $P = 2n + 6$ ($P = 14$ for $n = 4$) is the length of the process sequence. Both models allocate the same position capacity $P = 2n + 6$ so that every parameter matrix has the exact same dimensions in both programs:

  • Shared prompt (positions $0 \dots n+2$): $s_0$ at position $0$, query $q$ at position $1$, letters $w_1 \dots w_n$ at positions $2 \dots n+1$ (so $w_t$ sits at position $1+t$), and $\textsc{sep}$ at position $n+2$.
  • Process continuation (positions $n+3 \dots 2n+5$): intermediate states $s_1 \dots s_n$ at positions $n+3 \dots 2n+2$, followed by $\mathtt{:}$, $s_n$, and $\textsc{eos}$ at positions $2n+3, 2n+4, 2n+5$.
  • Outcome continuation (positions $n+3 \dots n+5$): skips the intermediate states and writes $\mathtt{:}$, $s_n$, and $\textsc{eos}$ directly at positions $n+3, n+4, n+5$.

Figure 1 · Sequence Layout (0-indexed positions above each token)

One structural consequence drives the entire construction below. In causal next-token prediction, position $i$ predicts token $i+1$. In the process row, the position that predicts $s_t$ is position $n+1+t$ (position $6$ holding $\textsc{sep}$ predicts $s_1$; position $6+t-1$ holding $s_{t-1}$ predicts $s_t$). Thus, the process model always sees its previous state $s_{t-1}$ on the page, whereas the outcome model never sees any intermediate state and must compute $s_n = (s_0 + \sum_{t=1}^n b_t) \bmod m$ in a single shot at the colon (position $n+3 = 7$).

2. Three Linear-Algebra Primitives

Writing Transformer weights by hand is like writing a small assembly program. Every weight matrix in both constructions is built from just three elementary facts:

  1. One-hot vectors test equality via dot products. Representing item $i$ by the basis vector $e_i$ (a $1$ at coordinate $i$ and $0$ elsewhere) turns equality testing into an inner product: $e_i \cdot e_j = \mathbf{1}[i = j]$.
  2. Two-input ReLU units form exact binary AND gates. With $\operatorname{ReLU}(x) = \max(0, x)$, for binary inputs $x, y \in \{0, 1\}$, \[ 2\,\operatorname{ReLU}(x + y - 1.5) = \begin{cases} 2 \cdot 0.5 = 1 & \text{if } x = 1 \text{ and } y = 1, \\ 0 & \text{otherwise (since } x + y - 1.5 \le -0.5\text{)}. \end{cases} \] Replacing $+y$ with $-y$ and shifting the threshold to $-0.5$ gives $2\,\operatorname{ReLU}(x - y - 0.5) = \mathbf{1}[x = 1 \wedge y = 0]$.
  3. Softmax with a large routing gap $\beta_n$ acts as a pointer or uniform average. With score gap $\beta_n = \max\{16,\, 3\log(8(n+3))\} = 16$, softmax concentrates almost all weight on the maximum-scoring entry, or splits it equally across tied winners: \[ \operatorname{softmax}(16, 0, 0, 0) \approx (1 - 3\cdot 10^{-7},\ 10^{-7},\ 10^{-7},\ 10^{-7}), \qquad \operatorname{softmax}(16, 16, 0, 0) \approx (\tfrac{1}{2}, \tfrac{1}{2}, 0, 0). \] Because softmax weights must sum to $1$, a position that has nothing to read in a given head is routed to a fallback position whose source slot is guaranteed to be zero, so copying from it adds $0$.

3. The Network Architecture & Residual Slot Encoding

The architecture is a two-block causal Transformer ($L = 2$ blocks, $H = 3$ heads per block, head dimension $P$, ReLU MLP of width $F$, no LayerNorm). Given a sequence of $T$ token IDs, the state of the network is a $T \times W$ matrix $X$ whose $i$-th row is the residual vector of position $i$:

\(X = E_{\mathrm{tok}}[\mathrm{ids}] + E_{\mathrm{pos}}[0{:}T]\)Input: token embedding + position one-hot
\(S_h = \bigl(X W_h^{Q\top}\bigr)\bigl(X W_h^{K\top}\bigr)^{\!\top} / \sqrt{P}\)Causal routing scores for head \(h \in \{0,1,2\}\)
\(X \mathrel{+}= \sum_{h=0}^{2} \operatorname{softmax}(S_h)\, X W_h^{V\top}\)Attention: load slots from earlier positions
\(X \mathrel{+}= \operatorname{ReLU}\bigl(X W_{\mathrm{in}}^{\top} + b\bigr)\, W_{\mathrm{out}}^{\top}\)MLP: compute new slots within each position
\(\mathrm{logits} = X R^{\top}\)Readout: score next token in \(\mathbb{R}^{|\mathcal{V}|}\)

Splitting the Residual Stream into Disjoint Named Slots

Think of the residual vector $x_i \in \mathbb{R}^W$ at position $i$ as a collection of named registers called slots, each occupying a fixed slice of coordinates. Attention is the only mechanism that loads a slot from another position ($W_V$ maps a source slot to a destination slot); the MLP computes new slots from slots already present at the same position.

Crucially, the input embeddings populate three disjoint slots:

  • A letter token ($a < A$) writes $e_a$ into TL and leaves TV all zero.
  • A state-value token ($A + v$) writes $e_v$ into TV and leaves TL all zero.
  • The delimiter tokens ($\textsc{sep}$, $\mathtt{:}$, $\textsc{eos}$) write zeros to both TL and TV.
  • Every position $i \in \{0, \dots, P-1\}$ writes its one-hot index $e_i$ into POS via $E_{\mathrm{pos}}$.

Every remaining slot starts at zero and is written by a single attention head or MLP sub-layer. Because letter tokens have zero TV and state tokens have zero TL, any head that copies TL can safely use position $0$ (which holds $s_0$, a state token) as its fallback, and any head that copies TV can safely use position $1$ (which holds $q$, a letter token) as its fallback.

4. Block 0: Finding the Marks (Identical in Both Programs)

Before counting can begin, both programs must determine which letters $w_t$ match the query $q$. Because an MLP operates on each position independently, testing $w_t = q$ requires bringing $q$ and $w_t$ into the same residual vector. Block 0 does this in two steps, using identical weights in both the process and outcome programs:

  1. Block 0, Head 0 ($\text{QRY} \leftarrow \text{TL}$): All heads share the identity key matrix $W^K[d, \text{POS}_d] = 1$, so the key of row $j$ is simply its position one-hot $k_j = e_j$. In Head 0, each letter position $i \in \{2, \dots, n+1\}$ sets $W^Q[1, \text{POS}_i] = C = 16\sqrt{P}$ to attend to position $1$ (which holds $q$), while every other position routes to fallback position $0$ (whose TL slot is zero). The value matrix sets $W^V[\text{QRY}_a, \text{TL}_a] = 1$ for $a < A$, copying $e_q$ into QRY at every letter position. Heads 1 and 2 of Block 0 are zero.
  2. Block 0, MLP ($\text{MATCH} \leftarrow \mathbf{1}[\text{TL} = \text{QRY}]$): Each letter position $1+t$ now holds $e_{w_t}$ in TL and $e_q$ in QRY. The MLP uses $A = 4$ ReLU AND-gates—one per letter $a \in \{\mathtt{a,b,c,d}\}$: \[ \text{MATCH} \mathrel{+}= \sum_{a=0}^{A-1} 2\,\operatorname{ReLU}\bigl(\text{TL}_a + \text{QRY}_a - 1.5\bigr) = \mathbf{1}[w_t = q] = b_t. \] Gate $a$ reaches pre-activation $+0.5$ (and output $2 \times 0.5 = 1$) if and only if both $\text{TL}_a = 1$ and $\text{QRY}_a = 1$. Every other gate has pre-activation $-0.5$ or $-1.5$ and stays off.

5. Block 1, Process Program: One Step at a Time

Counting is a loop: s = (s + mark) mod m. In the process format, the model's earlier outputs $s_1, \dots, s_{t-1}$ are already on the page, so Block 1 only needs to implement the loop body at each position $r = n + 1 + t$ (positions $6, 7, 8, 9$ for $t = 1, 2, 3, 4$):

  • Head 0 ($\text{PREV} \leftarrow s_{t-1}$): For $t = 1$, predicting position $n+2 = 6$ holds $\textsc{sep}$, so it attends to position $0$ to fetch $s_0$. For $t \ge 2$, predicting position $n+1+t$ already holds token $s_{t-1}$ in its own TV slot, so it attends to itself ($r \to r$). All other positions fall back to position $1$ ($q$, whose TV is zero). $W^V$ copies $\text{TV} \to \text{PREV}$.
  • Head 1 ($\text{MT} \leftarrow b_t$): Predicting position $n+1+t$ looks $n$ positions back to letter position $1+t$ (which holds $w_t$ and its mark in MATCH). Fallback is position $0$ (no mark). $W^V$ copies $\text{MATCH} \to \text{MT}$.
  • Head 2 ($\text{OUT} \leftarrow s_n$ at the colon): At the colon (position $2n+3 = 11$), the final state $s_n$ has already been written at position $2n+2 = 10$. Head 2 routes $2n+3 \to 2n+2$ and copies $\text{TV} \to \text{OUT}$ directly so the answer is repeated after the colon without further arithmetic.
  • Block 1 MLP ($2m$ transition gates): At each predicting position $n+1+t$, PREV holds $e_{s_{t-1}}$ and MT holds $b_t \in \{0, 1\}$. Two ReLU gates per state $j \in \{0, \dots, m-1\}$ encode the full transition table: \[ \underbrace{2\,\operatorname{ReLU}(\text{PREV}_j - \text{MT} - 0.5)}_{\text{was } j,\ \text{no mark } (b_t = 0)} \to \text{OUT}_j, \qquad \underbrace{2\,\operatorname{ReLU}(\text{PREV}_j + \text{MT} - 1.5)}_{\text{was } j,\ \text{mark } (b_t = 1)} \to \text{OUT}_{(j+1)\bmod m}. \] Because the same $2m$ units run at every step $t$, the process MLP size does not depend on the word length $n$.

6. Block 1, Outcome Program: Everything at Once

Without intermediate states on the page, the outcome program must aggregate all $n$ marks and compute $(s_0 + c) \bmod m$ in a single forward pass at the colon (position $n+3 = 7$):

  • Head 0 ($\text{CNT} \leftarrow c = \sum_{t=1}^n b_t$): Addition is commutative, so attention can count by averaging. At the colon (position $n+3$), $W^Q$ assigns the same score $C$ to all $n$ letter positions $\{2, \dots, n+1\}$. Softmax gives each letter weight $1/n$, computing the average mark $\frac{1}{n}\sum_{t=1}^n b_t$. Setting $W^V[\text{CNT}, \text{MATCH}] = n$ rescales that average back into the exact integer count $c = n \cdot \frac{1}{n}\sum_{t=1}^n b_t$.
  • Head 1 ($\text{S0} \leftarrow s_0$): The colon attends to position $0$ and copies $\text{TV} \to \text{S0}$, loading $e_{s_0}$. Head 2 is all zero.
  • Block 1 MLP ($3m(n+1)$ units: one triangle bump per $(s_0, c')$): A piecewise-linear ReLU network cannot compute the sawtooth function $(s_0 + c) \bmod m$ with a constant-size formula because the output wraps around every $m$ steps. Instead, for each start state $j \in \{0, \dots, m-1\}$ and each candidate count $c' \in \{0, \dots, n\}$, three ReLU units with thresholds at $c'-1,\, c',\, c'+1$ and output weights $(+1, -2, +1)$ form a triangle bump (hat function) centered at $c'$: \[ \beta_{c'}(c) = \operatorname{ReLU}(c - c' + 1) - 2\,\operatorname{ReLU}(c - c') + \operatorname{ReLU}(c - c' - 1) = \mathbf{1}[c = c'] \quad \text{for all } c \in \mathbb{Z}. \] To select the active start state $s_0 = j$, each unit also reads $\text{S0}_j$ with weight $n+2$ and subtracts $n+2$ in its bias: \[ z_{j, c', \chi} = \text{CNT} - c' + \chi + (n+2)(\text{S0}_j - 1), \qquad \chi \in \{+1, 0, -1\}. \] When $\text{S0}_j = 1$, the gate term cancels; when $\text{S0}_j = 0$, the pre-activation is shifted down by $n+2 \ge c + 2$, keeping all three ReLUs strictly negative. Bump $(j, c')$ writes to $\text{OUT}_{(j+c') \bmod m}$, requiring $3m(n+1)$ units ($30$ units for $n=4, m=2$), which grows linearly with $n$.

7. Readout, Free-Running Inference & Attention Maps

The readout matrix $R \in \mathbb{R}^{|\mathcal{V}| \times W}$ converts the final residual stream into token logits $z = X R^{\top}$:

  • State-value tokens ($A + v$): read $\text{OUT}_v$ with weight $20$, so $\text{OUT} = e_v$ produces logit $20$ on token $A+v$ and $0$ on all other state values.
  • Colon ($\mathtt{:}$) and $\textsc{eos}$: are emitted by position clock rather than state computation—$R[\mathtt{:}, \text{POS}_{\text{colon\_at}}] = 20$ and $R[\textsc{eos}, \text{POS}_{\text{eos\_at}}] = 20$, where $(\text{colon\_at}, \text{eos\_at}) = (2n+2, 2n+4)$ for process and $(n+2, n+4)$ for outcome.

Pass-by-Pass Autoregressive Generation

At test time, the model is given only the prompt (rows $0 \dots n+2$) and generates one token per forward pass by greedy argmax on the last row's logits, appending each predicted token to the input of the next pass. Because the causal mask prevents any row $i$ from reading rows $j > i$, running a single forward pass on the completed sequence produces the exact same activations and logits at every row as pass-by-pass autoregressive decoding. Because both programs live inside the exact same parameter space and achieve $100\%$ accuracy on every input, the failure of standard outcome training is not a failure of capacity. Rather, outcome supervision asks gradient descent to discover a global count-and-wrap circuit from a single end-of-sequence bit whose correlation with any individual letter mark vanishes as $n$ grows, whereas process supervision supplies a local, constant-size transition target at every step.
